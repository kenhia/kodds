Which Qwen3 reads the odds best, beside klams on a 16 GB card

kodds turns a local model's next-token log-probabilities into a probability for each answer choice. Four quantised Qwen3 builds ran the same 154 labelled homelab questions on kubs0's RTX 4080 SUPER, with klams' two embedding servers left running throughout.

How a choice is scored

Every token of the answer counts, and so does stopping

A choice's score is the sum of the log-probs of all its tokens, then the end-of-turn token. Reading only the first token can't work here: five of the eight project names start with the bare token k.

…</think>\n\n→ k-homelab<|im_end|>

log P(k-homelab) = log p(k) + log p(-h | k) + … + log p(<|im_end|> | …ab). The end-of-turn token makes the score mean “the answer is exactly this”. Without it, Mars would always beat Mars bar, because every continuation of “Mars” counts toward it.

Then normalise across the choices. A real routing item from the 4B diagnostic, labelled kpidash. Raw summed log-probs on the left, probabilities after log-sum-exp on the right:

The model chose kmon, narrowly and wrongly. The raw numbers near 0 mean the model put almost all of its mass on those two names; this isn't a scoring artefact.

Fit

All four fit beside klams, with room to spare

klams TEI embedders (2.8 GiB, untouched every run) kodds model, default kodds model, other free

Peak memory for the whole GPU, sampled from nvidia-smi every 250 ms while the model loaded and ran all 154 items (n_ctx 1024, all layers offloaded). Loading took 0.8–1.3 s for every model. Nothing needed kai's 5090.

Accuracy by task

Size beats bits, and routing is hard for everyone

8B Q8_0 buys nothing over Q6_K for 1.7 GiB more, while 14B at 4-bit wins every task. Severity (kmon's ok / attention / problem call) and email triage are usable already. Routing a work item from its title and eight one-line project descriptions tops out at 47% (chance is 12.5%, the dashed line), and the misses are confident.

Calibration

Every model is sure; none is that right

accuracy mean confidence in its pick

The red gap is overconfidence: 24–41 points for every model. The raw probabilities rank the choices well, but you can't set a threshold on them yet.

Is it fixable?

One temperature recovers a fifth to a third of the Brier score

raw softmax(log-prob / T), T fitted on the other half

Two-fold cross-validated: T is fitted on alternate items and scored on the rest, both ways round. The fitted T is about 10 for all four (9.6–12.8), so the overconfidence is systematic and a calibration step can remove much of it.

Decision

Default: Qwen3-14B Q4_K_M. Fallback: 8B Q6_K

It had the best accuracy and the best Brier score, both raw and after temperature scaling, and it won every task. It fits beside klams' embedders at about 95 ms a call. It also uses the most VRAM, so if the embedders grow, 8B Q6_K (9.3 GiB peak) is the fallback, at about 9 points less accuracy.

What comes next

  • Calibration: fit a temperature for each task on the eval set. This data says one T already recovers about a third of the Brier score for the 4B and a fifth for the 14B.
  • Routing input: before a korg routing consumer ships, try the work item's full text, fuller project descriptions and a few worked examples. That's prompt work, not a bigger model.
  • 002 — service: an HTTP endpoint on kubs0 with the model kept loaded.
